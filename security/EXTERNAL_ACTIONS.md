# Что нужно сделать вручную (нужен доступ к аккаунтам)

Эти шаги нельзя сделать из кода. Отсортированы по важности.

1. **Второй фактор для админки конструктора (SEC-16, Medium).** Общий пароль открывает все 122 сайта.
   Cloudflare → Zero Trust → Access → Applications → Add → Self-hosted: домен `atlas.genkai.workers.dev`,
   путь `/admin*`; политика — Allow, Emails: ваша почта (вход по одноразовому коду из письма). Бесплатно до 50
   человек. Админки сайтов клиентов (`<сайт>/admin`) под Access не ставить — у клиентов свой пароль.
2. **Права токена Cloudflare.** Секрет `CF_API_TOKEN` у воркера `atlas` нужен для «Опубликовать» и «Свой домен».
   Создайте новый токен только с правами: Account → Workers Scripts: Edit, Account → Account Settings: Read,
   Zone → Zone: Edit, Zone → Workers Routes: Edit (на нужные зоны). Положите его командой
   `npx wrangler secret put CF_API_TOKEN` и удалите старый токен в профиле Cloudflare. Старый токен однажды
   передавался в переписке — его стоит отозвать в любом случае.
3. **Смена общего пароля.** Пароль владельца конструктора передавался в чате. `npx wrangler secret put
   ADMIN_PASSWORD` — после смены все ваши прежние сессии закроются сами (SEC-03).
4. **Резервные копии.** D1 хранит историю 30 дней (Time Travel, план Workers Paid): восстановление —
   `npx wrangler d1 time-travel restore atlas --timestamp=<время>`. Раз в неделю делайте выгрузку:
   `npx wrangler d1 export atlas --remote --output=backup-$(date +%F).sql` и храните её не в репозитории.
   R2 `atlas-media` копий не хранит — при необходимости включите репликацию на второй бакет.
5. **Публичный доступ к R2.** Убедитесь, что у бакета `atlas-media` выключен Public access (R2 → бакет →
   Settings): фото отдаются только через воркер.
6. **Двухфакторный вход в сами аккаунты** GitHub и Cloudflare — включить, если ещё не включён.
7. **Telegram-боты клиентов.** Токен бота показывается только при подключении; если клиент считает, что токен
   утёк, — `/revoke` в @BotFather и «Подключить» заново.
