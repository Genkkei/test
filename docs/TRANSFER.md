# Перенос сайта заказчику

Сайт переезжает полностью: код — в GitHub заказчика (приватный репозиторий), сайт, база и фото — в его
Cloudflare. После этого он не зависит от нас.

## Как перенести

1. Админка → «Перенос заказчику» (или у сайта кнопка «Перенести заказчику»). Обычно переносят копию,
   сделанную через «Выдать клиенту».
2. «Создать ссылку для заказчика» → «Скопировать сообщение» → отправить заказчику.
3. Заказчик по ссылке подключает GitHub и Cloudflare: кнопки открывают создание ключей с уже выставленными
   правами, ему остаётся нажать «Создать» и вставить ключ. Пароли от аккаунтов он никому не передаёт.
4. Когда у вас оба пункта зелёные — «Перенести». Код уходит в его GitHub, GitHub сам выкладывает сайт в его
   Cloudflare (3–6 минут, ход виден на экране).
5. Готово: адрес, админка и пароль — у вас и у заказчика на странице. «Скопировать сообщение» — итог для него.
6. Необязательно, когда заказчик проверил сайт у себя: «Отключить у нас» — адрес сайта в нашем аккаунте
   удаляется (необратимо; демо из каталога не отключается).

## Что получает заказчик

- репозиторий с кодом сайта (только его сайт и его шаблон, без чужих сайтов и наших документов);
- воркеры `<сайт>-app` и `<сайт>` (адрес `https://<сайт>.<его поддомен>.workers.dev`), базу D1 и хранилище R2;
- админку с паролем; каждый push в `main` выкладывается сам (GitHub Actions, бесплатных минут хватает).

## Если что-то не так

- «Ключу не хватает прав» — заказчик создаёт ключ заново по кнопке (права там уже стоят).
- «R2 не включён» — Cloudflare → R2 → включить (бесплатный объём; Cloudflare просит карту для проверки).
- Выкладка не прошла — ссылка «журнал» на экране ведёт в GitHub Actions заказчика; после исправления —
  «Повторить выкладку». Ключи заказчика удаляются из нашей базы, только когда перенос завершён.
